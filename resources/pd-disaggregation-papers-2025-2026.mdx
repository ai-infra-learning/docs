本文只收录直接研究 Prefill-Decode（P/D）执行边界、资源池、调度或 KV Cache 跨阶段传输的工作。检索截止时间为 **2026 年 8 月 16 日**，外链状态复核于 **2026 年 8 月 24 日**，来源限于论文原文、作者项目页和官方代码仓库。

## 结论

2025–2026 年的研究重点已经从“把 Prefill 和 Decode 放到两组 GPU”转向三个更具体的问题：动态调整 P/D 边界与资源比例；在多轮、突发和异构负载下决定 Prefill 应在哪里执行；降低 KV Cache 传输对 TTFT 的影响。

## 2025 年：固定分离走向动态边界

2025 年的论文主要修正静态 P/D 资源池的两个缺陷：KV Cache 传输开销，以及输入/输出长度变化造成的阶段负载失衡。

## 2026 年：多轮负载与动态 Prefill 路由

2026 年的新工作不再假设每次请求只有一次完整 Prefill。多轮对话和 Agent 工作流包含大量短 Append-Prefill，研究开始根据请求、队列和网络状态动态决定这些 Token 的执行位置。

| 时间 | 论文与核心新意 | 实验对象与论文结果 | 架构判定 | 代码状态 |
|---|---|---|---|---|
| 2026-02 | [Efficient Multi-round LLM Inference over Disaggregated Serving](https://arxiv.org/abs/2602.14516) 提出 AMPD，根据实时队列决定增量 Prefill 在 P 节点还是 D 节点执行，并用 Prefill 重排与离线规划联合选择 P/D 并行配置。 | 4 台 8×H20-96GB 服务器，Qwen3-32B、Llama 3.1 70B、Mixtral 8×7B，ToolBench、GAIA、HotpotQA、DuReader；相对 Dynamo 的 SLO Attainment 平均提高 67.29%，相对共置 vLLM 平均提高 339.74%。 | **动态 P/D**：保留独立池，但部分增量 Prefill 可以在 Decode 侧执行。 | 论文未提供代码链接。 |
| 2026-03 | [Not All Prefills Are Equal: PPD Disaggregation for Multi-turn LLM Serving](https://arxiv.org/abs/2603.13358) 区分 Full Prefill 与 Append-Prefill。PPD 根据 SLO 和负载，把后续轮次的轻量 Append-Prefill 留在持有 KV Cache 的 Decode 节点。 | vLLM 原型、4×H100、ShareGPT 与 WildChat；Full Prefill 与 Append-Prefill 对 TPOT 的干扰约为 48% 与 2%，PPD 将后续轮次 TTFT 平均降低约 68%，并在测试点保持稳定服务。 | **动态 P/D**：首轮使用经典 P/D，后续轮次可在 D 节点本地 Prefill。 | [官方代码](https://github.com/freelulul/vllm-ppd)已公开，仓库标注 ICML 2026。 |
| 2026-05 | [KVServe: Service-Aware KV Cache Compression for Communication-Efficient Disaggregated LLM Serving](https://arxiv.org/abs/2605.13734) 将 KV 压缩方法组成可搜索策略空间，通过离线贝叶斯搜索和在线 Bandit 按网络、SLO 与质量预算选择传输配置。 | 集成 vLLM，覆盖多种数据集、模型、GPU 与网络；在 P/D 分离场景最高获得 9.13 倍 JCT 加速，在 KV 状态分离场景最高降低 32.8 倍 TTFT。 | **不是新的 P/D 切分方案**：它以已有 P/D 或 KV 状态分离为前提，优化通信路径。 | [官方代码](https://github.com/hpdps-group/KVServe)已公开，包含 P/D Baseline 与测试脚本。 |

## 不应直接计入 P/D 新论文的工作

Chunked Prefill、Prefix Cache、KV Cache Offloading、远程 KV Store 和 Attention/FFN 分离都可能与 P/D 组合，但它们本身不等于 Prefill 与 Decode 位于不同 Worker。判断一篇论文是否属于 P/D，至少需要确认请求在 Prefill 后发生执行实例切换，或论文明确改变了这种切换边界。

semi-PD、Nexus、MuxWise 和 RAPID-Serve 的价值在于单 GPU 内的阶段隔离或复用。它们与 DistServe 式跨 GPU 分离解决相同的干扰问题，但没有相同的权重复制、KV 网络传输和独立扩缩容边界。KVServe、DualPath、SpectrumKV 则以 P/D 已经存在为前提，主要解决传输与存储瓶颈。
